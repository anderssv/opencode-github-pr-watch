# Desktop: pill and PRs tab

The pill and the PRs tab read one store of data, so they show the same thing: the pill is everything the session watches, and the PRs tab with "Current session only" lists the same watches. The store changes in two ways only: each watch's check sends its new row, which replaces just that row, and full refreshes (opening, the reload button, every 30 seconds for watches and every 3 minutes for the PR search) replace everything.

These need the OpenCode desktop app. Watching itself works in any OpenCode client.

## The pill above the composer

![The pill, opened](images/pill.png)

In OpenCode Desktop, a pill above the session's composer shows how many PRs the session watches ("3 PRs watched"), coloured by the one needing attention most: red when something failed, yellow when a person has to act. Clicking it lists each PR with where it is now ("checks running", "waiting for review", "deploying"…), with buttons that open the PR and its workflow run in the browser. The run is the one still going, else a failed one, else the latest: the PR's checks before merge, the deploy pipeline after. It updates as the watches change.

- The server part exposes the watches over RPC (`rpc.ts`: `pr-watch.list` and a `changed` event); the desktop part (`src/gui.tsx`, the experimental GUI plugin API) reads them.
- The desktop part is a prebuilt bundle: run `bun run build` (or `bun run dev` while changing it). `dist/` is not committed, so build after a fresh clone.

## The PRs tab in the side panel

![The PRs tab, grouped by topic](images/prs-topics.png)

A pinned "PRs" tab in the session's side region (shown by default) lists the open PRs the `gh` user created, in every repo (`gh search prs --author @me`), grouped by repo. One dropdown narrows it to one organisation, another sorts it: by name (repos A–Z), by newest PR, or by oldest PR (repos and their PRs; merged PRs by merge time). A "Show drafts" checkbox (on by default) hides draft PRs when off. A "Group by" dropdown groups by repo (folder icon, the default), by topic (list icon), or not at all ("None": one "All PRs" list, by repo then newest first for "Name", else by date). Topics come from a light model of the panel session's own provider (the same provider guard and model preferences as watches): it names 3–8 topics and puts each PR in one; code drops unknown PRs and puts any it left out under "Other". Topics are kept for the same set of PRs. When PRs come or go, the topics stay: PRs that are gone drop out (and an empty topic with them), and the model is only asked where the new PRs go, an existing topic or a new one if none fits. Only when there are no topics yet, or most PRs are new, does it make a whole new grouping; while they load, or if they can't be made (the reason is shown), the list stays grouped by repo. In topic view each PR also shows its repo. "Show PRs that aren't mine" (on by default) adds the watched PRs others opened (bots, colleagues), told apart by the PR's author. A merged PR whose watch is still going (deploying, waiting for approval) stays with the open PRs until the watch is done, then moves to "Recently merged". "Current session only" (off by default) narrows the tab to the PRs and runs the current session watches; others' PRs among them only show with "Show PRs that aren't mine". A sliders button next to the reload button chooses which buttons each PR line shows (open the watching session, the run, watch or stop, new session, GitHub); the choice applies to every session and to the pill, and is kept. A "Status" dropdown has an "All" checkbox and one per status (all on by default): Needs me (failed, changes requested, conflicts, ready for merge: something to fix, or the merge), Waiting for review, Waiting for approval (a run waiting for someone to approve it), In progress, Done, and Not watched. It filters the PRs, the merged PRs and the workflow runs. The dropdowns wrap onto more lines when the panel is narrow. Watches of runs without a PR are listed first under "Workflow runs". A watched PR has a button to open the session watching it. All these choices are remembered per session; a new session starts with the last choices made in any session. A status line at the top shows everything in progress with one spinner ("Loading your PRs…", "Sorting your PRs into topics…", "Starting watching o/r#42…", "Stopping watching …", "Starting a session about …"), then the latest result for a few seconds. PRs in My PRs use the same line as the watch lists: a watched PR shows its watch's status icon and where it is (from whichever session watches it), and its run links. A search field at the top filters both lists as you type: every word must be in the PR's title, repo or number (`#803` or `803`), in any case. The search is kept per session while the app runs, but not stored. Each group heading (repo or topic) has a copy button that puts its listed PRs on the clipboard as a list of `- <title>: <url>` lines, in the order shown. Each PR shows draft, age and whether it's watched, with buttons to watch it in the current session, to start a new session about it (in the current session's folder, with its provider, model and agent, titled "PR #N on owner/repo", whose first message asks for a summary of the PR) and to open it on GitHub. "Recently merged (7 days)" expands to the PRs merged in the last week. It reloads every 3 minutes and when a watch changes, only while the tab is on screen; the server keeps search results for a minute. Search can lag a few minutes behind a merge.
